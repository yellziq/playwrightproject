# UI-автотесты «Стройбаза №1»

Python, Playwright, pytest и Allure. Публичный набор проверяет каталог, страницу входа, ошибки ввода телефона и добавление товара в корзину.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest --alluredir=allure-results
```

Для просмотра отчёта установите Java и Allure CLI 2.34.1, затем выполните:

```bash
allure serve allure-results
```

Параметры запуска передаются через переменные окружения: `SB_BASE_URL` (по умолчанию `https://s-b-1.ru`), `SB_BROWSER` (`chromium`, `firefox` или `webkit`), `SB_TIMEOUT_MS` (`15000`). Для другого браузера установите соответствующий движок через `python -m playwright install`. Уровень логов задаётся через `--log-cli-level=DEBUG`, `INFO`, `WARNING` или `ERROR`.

## Покрытие задания

По [инструкции магазина](https://s-b-1.ru/blog/Lichnyy%20kabinet/) вход выполняется по номеру телефона и одноразовому коду. Телефон с паролем и email с паролем в инструкции не описаны. Наличие CAPTCHA требует проверки в браузере.

Проверки ТК-А01, ТК-А02, ТК-А03 и ТК-О22 основаны на исходной таблице тест-кейсов.
CAT-01, AUTH-01 и AUTH-02 проверяют доступность публичных страниц и формы входа.

## Показ преподавателю

Из папки проекта в терминале VS Code запустите отдельно проверку входа:

```bash
.venv/bin/python -m pytest -v autotest/test_login.py --manual-otp --alluredir=allure-results --clean-alluredir
```

1. Когда откроется браузер, курсор уже будет в поле «Телефон». Введите свой номер.
2. После ввода полного номера тест сам отметит согласие и нажмёт «Продолжить». Если сайт предложит выбрать способ получения кода, выберите его.
3. Введите шестизначный код из сообщения прямо в браузере. Тест поставит курсор в поле кода и нажмёт «Продолжить» после шестой цифры. На ввод отведено три минуты.
4. Вернитесь в терминал. Тест проверяет активную сессию по наличию ссылки выхода в личном кабинете и закрывает браузер. На успешном прогоне терминал покажет `1 passed`.
5. Покажите результаты через `allure serve allure-results`. В отчёте есть отдельный сценарий «ТК-А01 · Вход по существующему номеру» и шаг проверки сессии.

Для показа можно сказать: «ТК-А01 взят из моей таблицы. Playwright открывает форму в новой сессии и проверяет личный кабинет после входа. Номер и одноразовый код я ввожу в браузере. Для полностью автоматического прогона понадобится тестовый провайдер кодов». Этот вариант подтверждает активную сессию. Сверка ID аккаунта и проверка отсутствия новой записи из исходного кейса требуют доступа к тестовой среде. Создание заказа по ТК-О22 остаётся отдельным сценарием.

Без флага `--manual-otp` сценарии с личным аккаунтом пропускаются.

## Негативные проверки входа

ТК-А02 оставляет телефон пустым и проверяет сообщение «Логин должен быть не менее 3 символов.».
ТК-А03 вводит короткий телефон и проверяет сообщение «Указан некорректный номер телефона.».
Оба теста отмечают согласие, нажимают «Продолжить» и проверяют, что поле телефона остаётся видимым.
Ожидания обновлены по фактическим сообщениям публичного сайта.

```bash
.venv/bin/python -m pytest -v autotest/test_phone_validation.py --alluredir=allure-results
```

## Сценарий корзины на публичном сайте

Тест вводит «Правило 1000 мм» в поле «Поиск товара» на главной. Правило здесь — инструмент
для выравнивания штукатурки. Тест открывает карточку выбранного товара, добавляет одну штуку
и сверяет название, количество и сумму позиции с ценой карточки.

```bash
.venv/bin/python -m pytest -v autotest/test_cart.py --alluredir=allure-cart-results --clean-alluredir
allure serve allure-cart-results
```

## ТК-О22 — самовывоз с ручным подтверждением

Перед запуском оставьте корзину аккаунта пустой. В терминале VS Code запустите:

```bash
.venv/bin/python -m pytest -vs autotest/test_order.py --manual-otp --manual-order-confirm --alluredir=allure-results --clean-alluredir
```

1. Введите в терминале телефон, имя и фамилию получателя и email. Символы при вводе скрыты.
   Альтернативно можно передать их через локальные переменные `SB_TEST_PHONE`, `SB_ORDER_NAME`
   и `SB_ORDER_EMAIL`.
2. В открывшемся Chromium дождитесь кода и введите его. Программа сама введёт телефон,
   отметит согласие и нажмёт «Продолжить» на обоих шагах.
3. Playwright найдёт товар через поиск на главной, добавит две единицы, сверит корзину,
   выберет самовывоз и оплату при получении, заполнит данные покупателя и сверит итог.
4. Тест прокрутит страницу к финальной кнопке и будет ждать до трёх минут. Проверьте товар,
   сумму и способ получения. Нажатие «Оформить заказ» отправляет реальный заказ в магазин.
   Нажмите его сами, только если хотите оформить этот заказ.
5. После клика тест ждёт страницу подтверждения и проверяет, что на ней виден номер заказа.

Для публичного сайта используется товар из каталога по актуальной цене. Исходный ТК-О22
предусматривает фиксированный товар T1, цену и доступ к записи заказа на стенде. Этот прогон
проверяет состав и сумму перед подтверждением и номер на странице после него.

## Демонстрация на практике

### Видимый браузер, лог и скриншоты

```bash
SB_TIMEOUT_MS=45000 .venv/bin/python -m pytest -v --headed --slow-mo 250 --demo-artifacts --alluredir=allure-results --clean-alluredir
```

- `--headed` открывает видимый Chromium. `--slow-mo 250` добавляет 250 мс между действиями Playwright, чтобы за ними было удобно следить.
- В терминале найдите строку «Демо маскирования» с `phone=*** email=*** otp=*** password=***`. Она получена из вымышленных данных. [Функция маскирования](core/logging_mask.py) обрабатывает поля перед выводом записи лога. Код от магазина вводится прямо в браузере.
- Для отчёта выполните `allure serve allure-results`. Откройте успешный публичный тест, например «ТК-А02 · Пустой телефон», и разверните вложение «Скриншот для демонстрации». Флаг `--demo-artifacts` прикрепляет снимки и для успешных публичных тестов. В обычном режиме снимок прикладывается при падении публичного теста. Для тестов с личным аккаунтом вместо снимка указывается причина, поскольку страница может показывать личные данные.
- Для показа шагов входа и оформления используйте отдельные команды выше. Оба сценария уже работают в видимом браузере.

### Что показать в коде

- [ui/pages.py](ui/pages.py) → `AuthorizationPage`. `input[placeholder="Телефон"]` находит поле телефона, `#bx-authorize-policy-checkbox` — галочку согласия. Здесь же находятся действия с формой.
- [ui/shop.py](ui/shop.py) → `ShopPages` и `CheckoutPage`. Здесь описаны локаторы поиска, корзины, самовывоза и формы покупателя.
- [autotest/test_phone_validation.py](autotest/test_phone_validation.py) → готовый пример сценария. Сам тест задаёт шаги и ожидаемое сообщение, а `AuthorizationPage` выполняет действия на странице.
